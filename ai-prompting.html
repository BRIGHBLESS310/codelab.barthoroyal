Write clear, bounded prompts

A prompt gives a generative model instructions and context. Clear prompts state the task, provide relevant input, define the desired format, and identify boundaries or uncertainty behavior.

Key idea

Prompts influence output but do not guarantee correctness or safety. Do not put secrets or unnecessary personal information in a prompt, and validate output before relying on it.

Reduce ambiguity and set expectations

A useful prompt states the task, supplies relevant context, and makes the expected response clear. Concrete instructions such as audience, scope, and length reduce guesswork. Examples can demonstrate the pattern, but they should represent valid cases and not accidentally contradict the instruction.

Bound the source material when accuracy matters: tell the model what information it may use and how to respond when that information is insufficient. A prompt can guide behavior but cannot guarantee correctness, so verify important claims and validate output before relying on it.

Treat prompts as versioned inputs to a system. Change one element at a time, compare results on a small set of realistic and edge-case questions, and retain the versions that meet your criteria. This connects prompt writing to evaluation rather than relying on one impressive demonstration.

Example

The prompt sets a scope, format, and uncertainty rule. A separate application check should still confirm the output uses the required format and is faithful to the source.

prompt = """
Task: Summarize the supplied text in two bullets.
Use only facts present in the text.
If a detail is missing, say it is not stated.

Text: {document}
"""

Practice

Rewrite a vague request such as 'tell me about this' into a bounded task with a specific audience, format, and rule for missing information.

Try the example, change one detail, and explain how the result changes.
