Follow a disciplined ML workflow

A typical workflow defines a task, collects and prepares data, trains a model, evaluates it on held-out examples, and monitors it after release. Each stage can reveal reasons not to proceed.

Key idea

Keep training, validation, and test data separate. Decide on a baseline and evaluation metric before tuning so you can tell whether a change really helps.

Why the workflow is iterative

A machine-learning workflow begins with a defined outcome, then checks whether data and a model can support it. Data preparation, baseline selection, training, and evaluation build on one another, but results often send the team back to refine the question or correct a data issue.

A baseline is a simple reference—such as a rule or majority-class predictor—that makes it possible to measure whether a more complex model improves anything. Split data carefully, fit transformations only on training data, and keep a final test set untouched until decisions are complete to reduce leakage.

Evaluation is not the final step: deployment changes the context, and data may shift over time. Monitor whether quality and error rates remain acceptable, then define when to retrain, roll back, or stop using the model. This makes the workflow a continuing lifecycle rather than a one-time training script.

Example

The test split is reserved for a final estimate rather than repeated tuning. In practice, the split method and metric depend on the task and data structure.

train, validation, test = split(records)
model = fit(train)

settings = choose_settings(validation)
score = evaluate(model, test)
print(score)
