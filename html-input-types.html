Input Types

Explore input types through a practical example and a focused exercise.

How it works

Input types communicate the kind of data expected and can offer helpful controls on different devices. A placeholder is not a label.

Build the mental model

The type of an input communicates the expected value and can provide a suitable on-screen keyboard or native control. For example, email, number, date, and checkbox each offer behavior suited to a different kind of data.

How to apply it

The input type participates in browser validation and exposes meaning to assistive technology and autofill. Use name to identify the submitted value, and pair each control with a visible label and any needed instructions.

Common pitfalls

Do not pick an input type just for its appearance; a number control is not appropriate for a postal code that may start with zero or contain letters. Native validation is a helpful user aid, not a security boundary or a replacement for server-side checks.

<label for="date">Visit date</label>
<input id="date" name="date" type="date">
<label for="guests">Guests</label>
<input id="guests" name="guests" type="number" min="1" max="8">

Test each type with both a realistic value and a deliberately unsuitable one, and note the behavior supplied by the browser rather than by custom code.

Practice

Add date and checkbox controls to a form. Give them appropriate labels and constraints.
