Tables

Explore tables through a practical example and a focused exercise.

How it works

Tables present data with row and column relationships—not page layout. Add headers so users understand what each value represents.

Build the mental model

A data table represents relationships between values arranged in rows and columns. Use th for header cells and td for data, with a caption when a short title would help explain what the table compares.

How to apply it

Assistive technologies need to associate a data cell with the appropriate row or column header. Use a simple header structure where possible, and add a scope such as col or row when it clarifies that relationship.

Common pitfalls

Tables are not a page-layout grid: using them to position unrelated content produces confusing navigation and is hard to adapt to small screens. Keep the table's data relationships clear and provide a responsive treatment for wide tables.

<table>
  <caption>Workshop schedule</caption>
  <thead><tr><th scope="col">Time</th><th scope="col">Session</th></tr></thead>
  <tbody><tr><td>9:00</td><td>Welcome</td></tr></tbody>
</table>

Trace one data cell back to the row and column headers that explain it, then check whether the caption makes the dataset's purpose clear.

Practice
