Metadata and the Head

Explore metadata and the head through a practical example and a focused exercise.

How it works

The head contains metadata and references that describe or configure a page. Most head elements are not shown in the body.

Build the mental model

Metadata in the head describes or configures a document rather than appearing as ordinary page content. The character encoding, viewport, title, description, and linked stylesheets serve different consumers, including browsers, search previews, and assistive technologies.

How to apply it

The title should identify this particular page, not merely repeat a site name. A meta description can summarize the page for a search-result preview, while the viewport declaration helps the browser map CSS pixels to a device's available width.

Common pitfalls

Metadata is not a substitute for visible, well-structured content: a description does not create a page heading, and a title does not label an on-page section. Keep metadata inside head and avoid duplicate or misleading titles across pages.

<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="description" content="A guide to urban gardening.">
  <title>Urban Gardening Guide</title>
  <link rel="stylesheet" href="styles.css">
</head>

For each head entry, identify which browser or external service uses it; then compare the document title with the visible main heading.

Practice

Write the head for a recipe page with a useful title, description, viewport, and stylesheet link.
