Minimize and protect user data

Privacy-aware development considers what data is collected, where it is processed, who can access it, how long it is retained, and how users can exercise applicable rights.

Key idea

Use data minimization and purpose limitation. Redact unnecessary sensitive fields, restrict logs, set retention rules, and assess legal or contractual requirements with qualified stakeholders.

Minimize data across the entire request path

Privacy planning begins with identifying personal or sensitive information in user inputs, retrieved context, logs, evaluation data, and provider requests. Decide what is necessary for the task and remove or transform unrelated details before they leave the trusted boundary.

Understand the model provider's retention, processing, and access terms; do not assume an API request is private by default. Protect credentials, restrict data access, set retention limits, and ensure logs do not casually capture full prompts or responses. Follow applicable organizational and legal requirements.

Data minimization also reduces harm if an account, log, or service is exposed. Explain relevant collection and use to users, provide deletion or correction routes where appropriate, and reassess data flows when a feature changes. Privacy is an architectural property as well as a policy statement.

Example

The payload includes only fields needed for the feature and avoids routine logging of full content. Exact controls depend on the system and applicable obligations.

payload = {
    "question": redact_unneeded_identifiers(user_question),
    "locale": required_locale,
}

# Do not log full prompts or responses by default.

Practice

Create a data-flow inventory for an AI feature: fields, purpose, destination, retention, access, and deletion path.
