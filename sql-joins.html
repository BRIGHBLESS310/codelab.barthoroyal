Joins

Joins combine rows from related tables. INNER JOIN returns matching pairs; LEFT JOIN keeps every row from its left table and uses NULL for missing matches. One-to-many relationships can produce multiple result rows per parent.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

A join combines rows according to a relationship condition. ON states which key values match; qualifying table names or aliases keeps similarly named columns clear and makes the relationship easy to review.

An inner JOIN returns matching pairs. A LEFT JOIN preserves every row from its left input and fills right-side columns with NULL when there is no match. Choose based on whether unmatched parents should remain.

Joins can multiply rows: a customer with several orders appears once per matching order. This is expected one-to-many behavior, not necessarily duplicate data. COUNT after a join therefore counts joined rows unless you deliberately count distinct entities.

The example links each order to its customer and returns the name with the order date. Verify the key relationship and expected row count before adding aggregates or additional joins.

Example

SELECT customers.name, orders.order_date
FROM customers
JOIN orders ON orders.customer_id = customers.customer_id;

Practice

Join two related tables and determine how multiple child records affect the result count.
