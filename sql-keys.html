Keys and Relationships

Primary keys uniquely identify rows. A foreign key links a column to a referenced key. Relationships can be one-to-one, one-to-many, or many-to-many; a join table commonly represents the last type.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

A primary key uniquely identifies a row and should remain stable; it can be one column or a carefully chosen composite. A foreign key references a key in another table, connecting records while preserving referential integrity.

A one-to-many relationship places the parent's key in the child table, as customer_id does in orders. A many-to-many relationship normally uses a junction table with a foreign key for each side.

NOT NULL and foreign-key constraints prevent missing references, but enforcement settings vary. Verify integrity is enabled in your engine and decide whether deletes should be blocked, cascaded, or handled explicitly.

The schema fragment gives each order a primary key and requires a customer and date. A foreign key alone does not make the relationship one-to-one; use uniqueness constraints when only one related row is allowed.

Example

CREATE TABLE orders (
  order_id INTEGER PRIMARY KEY,
  customer_id INTEGER NOT NULL,
  order_date TEXT NOT NULL,
  FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
