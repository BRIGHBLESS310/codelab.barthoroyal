Prepare examples responsibly

Training and evaluation data represent the world through selected examples and labels. Missing, incorrect, outdated, or unrepresentative data can make a model unreliable for some situations.

Key idea

Check that you have permission to use data, collect only what is needed, document how it was obtained, and look for duplicates, missing fields, skew, or sensitive information.

Data shapes what a model can learn

A data example contains observations represented as features. For a support request, features might include its text and an agreed category label; a model can only learn patterns represented in the examples it receives. Missing, inconsistent, or misleading representations limit the usefulness of later modeling.

Data quality is not only about correct formatting. Check whether records reflect the people and situations the system will serve, whether labels are applied consistently, and whether collection was appropriate. Duplicate records or examples that leak the answer can make evaluation results look stronger than real-world performance.

Keep a clear account of data origin, purpose, access, and retention. Use only data that is necessary and authorized, and treat sensitive attributes carefully. These checks connect the technical preparation of a dataset to privacy, fairness, and responsible deployment.
