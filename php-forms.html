Forms and Request Data

HTML forms send request data to the server. Values in $_GET and $_POST are untrusted: check the request method, ensure fields exist, validate formats, and provide helpful errors.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

HTML forms send request data to the server. Values in $_GET and $_POST are untrusted: check the request method, ensure fields exist, validate formats, and provide helpful errors.

Forms submit named controls using a request method such as GET or POST. Check the request method before processing, then handle fields that may be absent. Trim and validate values on the server even when the HTML form has required fields, because clients can bypass browser checks.

Validation asks whether a value has the expected meaning or format; escaping makes it safe for the place it is displayed. Escape output when rendering user-provided text, and use CSRF protections for state-changing requests in real applications. Never trust a submitted field merely because it came from your own page.

Example

<?php
$name = "";
if ($_SERVER["REQUEST_METHOD"] === "POST") {
    $name = trim($_POST["name"] ?? "");
}
?>
<form method="post">
  <label>Name <input name="name" required></label>
  <button type="submit">Send</button>
</form>

Run or adapt this example in an appropriate local learning environment. Pay attention to the inputs, the result, and any assumptions the code makes.

Practice

Build a form that rejects blank names on the server and displays an escaped response.
