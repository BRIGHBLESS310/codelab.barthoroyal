Organizing Stylesheets

Explore organizing stylesheets through a practical example and a focused exercise.

How it works

Consistent grouping and meaningful class names make stylesheets easier to maintain. Remove obsolete rules and avoid unexplained overrides.

Build the mental model

A stylesheet is easier to maintain when related rules have a predictable order and component boundaries are clear. Group global foundations, layout rules, and component styles so a teammate can locate the source of a visual decision.

How to apply it

Reusable class names should describe a component or role rather than a temporary appearance. Consistent naming and small, focused rules reduce accidental overlap and make it easier to change a component without rewriting unrelated pages.

Common pitfalls

Copying the same declaration into many selectors invites visual drift, while excessive abstraction can make a simple style difficult to find. Keep one source of truth for shared values and remove obsolete rules when a component changes.

/* Components */
.site-header { ... }
.card { ... }
.card__title { ... }
/* Utilities */
.visually-hidden { ... }

Trace one visible component from its HTML class to the stylesheet rule, and identify which organization choice makes that relationship easiest to maintain.

Practice

Refactor a small stylesheet by grouping base, layout, and component rules. Rename vague classes.
