Form Validation

Explore form validation through a practical example and a focused exercise.

How it works

Built-in constraints catch common input mistakes before submission. A server must still validate submitted data.

Build the mental model

HTML constraint attributes such as required, minlength, max, and type="email" let the browser catch common input mistakes before submission. The constraint should match a real rule the user can understand.

How to apply it

Validation works best when the form identifies the problem and explains how to fix it. Keep labels and instructions available before entry, preserve the user's values after an error, and provide a clear success or error state rather than relying only on color.

Common pitfalls

Client-side checks can be bypassed, so the server must validate and safely handle every received value. Avoid constraints that reject legitimate user input, and do not claim a format is valid merely because it passes a browser's basic syntax check.

<label for="username">Username</label>
<input id="username" name="username" required minlength="3" maxlength="20">
<label for="email">Email</label>
<input id="email" name="email" type="email" required>

Try an empty required field and a malformed email in the example; compare the browser's immediate feedback with the validation the receiving service would still need.

Practice

Add required and length constraints to a registration form. Try submitting empty and invalid values.
