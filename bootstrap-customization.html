Customization and Theming

Explore customization and theming through a practical example and a focused exercise.

How it works

Bootstrap can be customized through Sass before compilation, or layered with a small stylesheet after Bootstrap.

Build the mental model

Bootstrap can be extended with utility and component classes, custom CSS, or Sass variables before the framework is compiled. Sass customization changes the generated design system, while a CSS override affects the final stylesheet through normal cascade rules.

How to apply it

Choose an approach based on project scope: a small one-off rule may be a component class, while a shared theme token is better configured centrally. Keep the framework's generated output and your custom source clearly separated.

Common pitfalls

Overly broad overrides can unintentionally alter every Bootstrap component, and editing a generated file is often lost on rebuild. Match the framework version and understand the cascade instead of escalating specificity for every adjustment.

/* custom.css, loaded after Bootstrap */
:root { --bs-primary: #075985; }
.btn-primary { --bs-btn-bg: #075985; --bs-btn-border-color: #075985; }

Trace a customized value from its source to the rendered component, and decide whether the change is a global theme choice or a local exception.

Practice

Change a primary color consistently. Choose CSS overrides or Sass and explain why.
