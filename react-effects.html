Effects and Data Fetching

Effects synchronize a component with systems outside React, such as timers or network requests. They are unnecessary for values calculable during rendering. Clean up subscriptions and handle request loading, success, and failure.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

An Effect synchronizes React with something outside rendering, such as a timer, subscription, browser API, or network connection. useEffect runs after a render commits; dependencies tell React when synchronization must repeat.

An Effect may return cleanup. The clock clears its interval before the Effect re-runs or when the component unmounts, preventing duplicate subscriptions and background callbacks that are no longer needed.

Do not use an Effect just to calculate a value from props or state; calculate it during rendering. Development Strict Mode may repeat setup and cleanup to reveal missing cleanup, so Effects should be safe to repeat.

The clock initializes its display and installs a repeating timer. Real fetching also needs loading and error states, and must prevent an older response overwriting newer results after inputs change.

Example

import { useEffect, useState } from "react";

function Clock() {
  const [time, setTime] = useState(() => new Date());
  useEffect(() => {
    const timer = setInterval(() => setTime(new Date()), 1000);
    return () => clearInterval(timer);
  }, []);
  return <time>{time.toLocaleTimeString()}</time>;
}
