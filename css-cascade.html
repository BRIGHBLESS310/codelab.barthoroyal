Cascade and Specificity

Explore cascade and specificity through a practical example and a focused exercise.

How it works

When declarations conflict, the cascade considers origin, importance, specificity, and source order. Keep specificity predictable.

Build the mental model

The cascade resolves competing declarations by considering relevance, origin and importance, cascade layer, specificity, and source order. Specificity compares selector weight; later source order breaks a tie only after higher-priority cascade criteria are equal.

How to apply it

Inherited properties such as text color can flow from a parent to descendants, while many layout and box properties do not inherit. The computed value shown by developer tools reflects the winning declaration after these rules and value processing.

Common pitfalls

Adding !important to every conflict makes future changes harder rather than fixing the underlying priority. Prefer a clear component scope and simple selectors; check the cascade before assuming a declaration failed to load.

p { color: #334155; }
.notice { color: #9a3412; }
/* Equal-specificity later rules win. */

Follow the competing rules in the example from cascade priority through specificity to source order, and identify the one declaration that wins.

Practice

Predict which of two conflicting rules wins, then verify the result in browser developer tools.
