Table Design and Data Types

CREATE TABLE defines a table's shape. Choose types that represent the values and constraints that enforce rules close to the data. Exact type behavior can vary between database engines.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

CREATE TABLE defines the columns a row can contain. Choose types that represent the data accurately, and add NOT NULL, DEFAULT, CHECK, and PRIMARY KEY constraints to make invalid states harder to store.

A constraint is enforced for every writer, including scripts that bypass form validation. Application checks still improve error messages, but the schema is the shared integrity boundary for data.

Type systems differ between engines. SQLite is more flexible about storage classes than PostgreSQL, so do not assume a type name guarantees identical validation everywhere. Check the target engine before relying on type behavior.

The example defines an identifier, a required title, a default priority, and a range check. The constraints document the domain in the schema; choose limits from requirements and consider how future migrations may change them.

Example

CREATE TABLE tasks (
  task_id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  priority INTEGER NOT NULL DEFAULT 1
    CHECK (priority BETWEEN 1 AND 5)
);

Practice

Design a tasks or books table with a primary key, a required field, and a suitable default.
