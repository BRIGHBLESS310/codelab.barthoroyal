Filtering and Sorting

WHERE filters rows, ORDER BY sorts results, and LIMIT can cap the number returned. Use parentheses when mixing AND and OR. IS NULL checks missing values; comparisons with NULL do not behave like ordinary equality.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

WHERE decides which source rows qualify. A predicate such as city = a value is evaluated for each row; AND requires both conditions to be true, while OR needs only one. Parentheses make mixed conditions unambiguous.

ORDER BY sorts qualifying rows and can use multiple keys. Without it, row order is not guaranteed. LIMIT caps the number returned, but repeatable paging needs a unique tie-breaker so equal names do not move unpredictably.

SQL uses three-valued logic for NULL: a missing value is neither equal nor unequal to an ordinary value. Test it with IS NULL or IS NOT NULL, and remember that NULL can affect comparisons and aggregates.

In the example, both city and active must match before rows are sorted and capped. Change one predicate at a time to see its effect; application queries should bind values as parameters instead of concatenating user input.

Example

SELECT name, city
FROM customers
WHERE city = 'Lagos' AND active = 1
ORDER BY name
LIMIT 10;
