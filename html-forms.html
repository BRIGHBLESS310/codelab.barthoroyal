Forms and Labels

Explore forms and labels through a practical example and a focused exercise.

How it works

Forms collect user input. A label gives each control a visible and programmatic name; a form groups controls for submission.

Build the mental model

A form groups controls that collect values and submit them for processing. Each control needs an understandable name, an appropriate type, and an association with its label; the form's action and method describe how data is sent.

How to apply it

A label connected with a control's for and matching id makes the control easier to identify and gives its clickable target a useful size. Group related options with fieldset and legend when a shared question needs context.

Common pitfalls

A placeholder is an example or hint, not a replacement for a persistent label. Choose button types deliberately—an omitted type inside a form defaults to submit—and do not assume that styling a control alone makes its purpose accessible.

<form action="/signup" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required>
  <button type="submit">Sign up</button>
</form>

Click each label in the example and confirm it focuses its control; then identify exactly what is submitted when the form's button is activated.

Practice

Create a contact form with name, email, and message fields. Label every control and choose sensible names.
