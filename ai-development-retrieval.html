Ground answers in approved sources

Retrieval-Augmented Generation (RAG) first finds relevant passages, then supplies them as context for a generated answer. Retrieval can improve grounding, but it does not ensure the answer is correct or that sources are current.

Key idea

Restrict retrieval to authorized documents, preserve source references, and test both answerable and unanswerable questions. Make the system decline when evidence is insufficient.

Ground generation in selected evidence

Retrieval-augmented generation first searches a collection for passages relevant to a question, then provides those passages as context for a generative model. This can make answers more specific to approved or current material than relying only on the model's training.

Retrieval quality depends on the source collection, chunk boundaries, indexing, permissions, and ranking. A missing or poorly ranked passage may leave the model without evidence even when the answer exists in the source. Preserve document identifiers and access rules throughout retrieval.

Ask the model to stay within the supplied evidence and state when it is insufficient, then verify citations against the retrieved passages. Retrieval reduces some unsupported claims but cannot guarantee correctness or resist every misleading instruction in documents. Test no-result and conflicting-source cases explicitly.

Example

Retrieval is permission-aware and the empty-result path is explicit. The final response should link to the source material so users can verify important claims.

matches = search(approved_index, question, user_permissions)
context = choose_relevant_passages(matches)

if not context:
    return "No supporting information was found."
return generate_with_sources(question, context)

Practice
