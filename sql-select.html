SELECT and FROM

SELECT chooses the columns to return and FROM identifies the table. Name only columns you need: explicit selections are easier to read and avoid transferring unnecessary data. Aliases give result columns clearer names.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

A SELECT query has two essential parts: SELECT names the values to return, and FROM names the source table. This is projection: choosing useful columns instead of copying every field into the result.

An alias introduced with AS changes a result column's label without renaming the stored column. Clear aliases help reports and application code communicate what a value means, especially when expressions or joins are involved.

Prefer explicit column names to SELECT *. A later schema change can otherwise widen a result, expose an unnecessary field, or break code that depends on a particular column order.

The example returns two fields for every row in customers; it does not filter or sort them yet. The next topics add WHERE and ORDER BY, so consider each clause one step in shaping a result set.

Example

SELECT name AS customer_name, city
FROM customers;
