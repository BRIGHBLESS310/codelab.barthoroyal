Java Methods

A method is a named block of code that performs a task. Methods make programs easier to reuse, test, and understand by giving operations clear names.

Define and call a method

A method declaration includes a return type, name, parameters, and body. Call the method by its name and provide arguments that match its parameters.

static int add(int left, int right) {
    return left + right;
}

int result = add(3, 4);
System.out.println(result);

int is the return type here. A method that returns nothing uses void.

The declaration's parts describe how callers use the method: static means it belongs to the class rather than a particular object, the return type tells what comes back, and parameters define the inputs. A call executes the body and can store the returned result for later work.

A non-void method must return a value of the declared type on every path. Returning a result instead of printing it keeps calculation separate from presentation, so callers can display, compare, or combine that result as needed.

Parameters and return values

Parameters describe the inputs a method needs. Returning a value lets the caller use the result in another expression or store it.

static double calculateArea(double width, double height) {
    return width * height;
}

double area = calculateArea(4.0, 2.5);

Give parameters meaningful names and keep each method focused on one job.

Arguments are the actual values supplied at a call site, while parameters are the local names receiving those values. Java is pass-by-value: for an object parameter the copied value is a reference, so mutating the referenced object may be visible to the caller, but reassigning the parameter does not change the caller's variable.

Validate assumptions at the boundary of a method when invalid inputs could cause confusing results. A method with a small, clear contract is easier to reuse and test than one that silently depends on unrelated program state.

Void methods

A void method performs an action without returning a value.

static void printWelcome(String name) {
    System.out.println("Welcome, " + name + "!");
}

printWelcome("Ada");

A void method is appropriate when the purpose is an action, such as displaying a message or updating an object. It can still accept parameters to customize that action, but it does not produce a value for an expression.

Keep side effects understandable: a method named printWelcome indicates output, whereas a method named formatWelcome would more naturally return text. Clear method names help callers know whether a call changes or displays anything.

Method overloading

Methods may share a name when their parameter lists differ. The compiler selects the matching version from the argument types and number of arguments.

static int square(int value) {
    return value * value;
}

static double square(double value) {
    return value * value;
}

Changing only the return type is not enough to overload a method.

Overloading provides several convenient ways to perform a related task, such as accepting different numeric types. The compiler resolves which declaration to call from argument types and conversions before execution; the runtime type of an argument does not dynamically select an overload.

Avoid overload sets whose signatures are ambiguous or whose behavior differs unexpectedly. If two operations mean different things, distinct names can be clearer than relying on subtle conversion rules.

Write a method that accepts a temperature in Celsius and returns its Fahrenheit equivalent. Call it with several values and print the results.
