Java Classes and Inheritance

Classes define new reference types by grouping data and behavior. Objects are individual instances created from those class definitions.

Create a class and object

Fields store an object's state. A constructor initializes the object, and methods provide behavior. Use access modifiers to control which code can reach a field.

class Greeter {
    private final String name;

    Greeter(String name) {
        this.name = name;
    }

    String greet() {
        return "Hello, " + name + "!";
    }
}

Greeter greeter = new Greeter("Ada");
System.out.println(greeter.greet());

The keyword this refers to the current object. The constructor runs when new Greeter("Ada") creates an instance.

A class describes the shape and behavior of a type; an object is one concrete instance with its own field values. Calling a constructor with new allocates and initializes that instance, and the resulting reference lets other code use its accessible methods.

The constructor parameter and field can share a name because this.name explicitly selects the field on the current object. Making a field private keeps callers from bypassing the class's rules, while a final field can be assigned only during initialization.

Encapsulation

Encapsulation keeps an object's internal state protected and exposes clear operations. Private fields prevent other code from changing data without the class's rules being applied.

class Counter {
    private int value;

    void increment() {
        value++;
    }

    int getValue() {
        return value;
    }
}

Do not add getters and setters automatically for every field. Prefer methods that express useful behavior and preserve valid object state.

Encapsulation means that an object owns the rules for changing its state. A method such as deposit(amount) can reject an invalid amount before updating the balance, whereas a public balance field would let any caller create an impossible value.

Think of a class's public methods as a small interface to its implementation. Internal representation can then change later without requiring every caller to be rewritten, as long as the visible behavior stays consistent.

Inheritance and overriding

A subclass can extend a superclass and specialize its behavior. Use @Override so the compiler can check that a method really overrides one from its parent type.

class Animal {
    void speak() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    @Override
    void speak() {
        System.out.println("Woof");
    }
}

Inheritance is useful for a genuine “is a” relationship. If one class simply needs another class's functionality, composition is often easier to maintain.

An overriding method has the same compatible signature as an inherited instance method, and @Override asks the compiler to verify that relationship. A subclass can specialize behavior while callers that use the parent type continue to work.

Java classes have a single direct superclass, so deep inheritance trees can tightly couple types. Prefer a small hierarchy for stable shared concepts; when the relationship is “has a” rather than “is a,” store another object in a field and delegate to it instead.

Build a small model

For a library example, a Book class could hold a title and an availability state. A method such as borrow() can check availability before updating it. This keeps the rule close to the data it protects.

Model only the state and behavior needed by the problem. A useful design asks what must always be true for each object, then ensures constructors and methods preserve those invariants rather than exposing fields for arbitrary edits.

This connects classes to the earlier lessons: fields are variables with object lifetime, methods apply logic and conditions to them, and collections can hold groups of objects. Start with one object, test its behavior, then decide whether a relationship or hierarchy is truly needed.

Practice

Create a Book class with a private title and a method that prints a short description. Make two objects with different titles and call the method on both.
