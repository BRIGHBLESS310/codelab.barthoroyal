Validation and Safe Output

Validation checks a value's meaning and format. Escaping makes data safe for a particular output context; htmlspecialchars with UTF-8 is common for HTML text. These are different protections.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

Validation checks a value's meaning and format. Escaping makes data safe for a particular output context; htmlspecialchars with UTF-8 is common for HTML text. These are different protections.

Validation checks whether data meets the application's rules, such as a required field, allowed range, or expected email format. Perform it on the server because browser checks can be bypassed. Give useful feedback without treating an invalid value as successful.

Escaping is a separate step applied when output is generated. For HTML text and quoted attributes, htmlspecialchars with UTF-8 is a common defense; other contexts require their own encoding rules. Prepared SQL statements protect query values but do not replace validation or output escaping.

Example

<?php
$email = filter_input(INPUT_POST, "email", FILTER_VALIDATE_EMAIL);
if ($email === false || $email === null) {
    echo "Please provide a valid email address.";
} else {
    echo "Thanks, " . htmlspecialchars($email, ENT_QUOTES, "UTF-8");
}

Run or adapt this example in an appropriate local learning environment. Pay attention to the inputs, the result, and any assumptions the code makes.

Practice

Validate an email address and show either an error or the escaped accepted value.
