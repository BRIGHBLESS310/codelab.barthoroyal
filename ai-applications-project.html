Scope a small AI project

Useful AI projects begin with a real need and a testable goal. A narrow, low-risk prototype makes it possible to compare AI with simpler alternatives and learn from user feedback.

Key idea

Define success, failure, data boundaries, and a fallback before building. Keep a person responsible for reviewing uncertain or consequential outcomes.

Start with a narrow, testable use case

Choose one user, one task, and a clear point where the feature helps. A bounded prototype makes it possible to test whether AI adds value without turning an early experiment into an open-ended product promise. Define what the system will not do as carefully as what it will do.

Write success criteria before selecting a model: for example, whether suggestions save time while keeping unacceptable errors below an agreed limit. Compare an AI approach with a simple baseline, identify appropriate test cases, and account for operational cost and latency as part of the decision.

Map what information enters the system, who reviews outputs, and what happens when the model is uncertain or unavailable. A useful project plan includes privacy boundaries, failure behavior, and a way to learn from users. If a safe and useful outcome cannot be defined, reconsider the feature rather than adding AI by default.

Example

The baseline provides a comparison, and the user remains in control of the final category. This is a more measurable starting point than an open-ended 'add AI' project.

goal = "suggest a topic for a support request"

# Baseline: show a short list of topics.
# Prototype: suggest one topic and allow the user to change it.
# Measure: compare suggestions with user-selected topics.

Practice

Write a one-page brief for a low-risk AI feature: user need, baseline, data, success metric, risks, and a fallback.

Try the example, change one detail, and explain how the result changes.
