JavaScript Errors

Errors indicate that an operation could not complete as expected. Use try...catch when code can recover or show a useful message, and do not silently ignore failures.

Understand the topic

Errors reveal failed operations or assumptions

Syntax errors prevent parsing; runtime errors happen during execution; logic errors produce a valid but incorrect result. Recognizing the kind of failure narrows the search. An error object can provide a message and stack trace to help locate where execution went wrong.

Throw and catch with purpose

Use throw when a function cannot continue under its contract, and catch where the program can recover or communicate clearly. Keep try/catch narrow so unrelated failures are not hidden; inspect the error rather than discarding useful context.

Do not silently swallow failures

An empty catch leaves confusing behavior and hides bugs. Validate external input at boundaries, but avoid redundant checks. Asynchronous operations may reject promises, so handle failures with catch or try/await; error handling complements debugging.

Handle expected failures

When creating your own errors, include enough context to help diagnose the problem without exposing sensitive data.

try {
    const settings = JSON.parse("{ invalid }");
    console.log(settings);
} catch (error) {
    console.error("Settings could not be read.", error);
}

Practice

Wrap parsing of a user-provided JSON string in try...catch and display a helpful error.
