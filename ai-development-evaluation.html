Build an evaluation set

Evaluate AI features with representative examples, expected behavior, and task-specific criteria. Include ordinary cases, edge cases, ambiguous inputs, and requests outside the feature's scope.

Key idea

Measure before launch and after meaningful changes to prompts, models, data, or code. Combine automated checks with human review for dimensions that are hard to score mechanically.

Measure the whole feature, not one response

An evaluation set is a collection of representative inputs with expected outcomes or review criteria. Include common cases, important edge cases, and cases where the system should decline or ask for help. Keep examples separate from data used to tune prompts or select models.

Score the dimensions that matter to users: task completion, factual support, format validity, safety, and latency may all matter. Use automated checks for objective properties and human review for qualities that resist simple rules. Inspect individual failures instead of relying solely on an aggregate score.

Run evaluations whenever prompts, models, retrieval, or application logic change. Compare against a baseline and agree on release thresholds before seeing results. A repeatable evaluation process helps detect regressions, but it cannot prove that every future input will be safe or correct.

Example

The examples test both a supported information need and an out-of-scope privacy request. Evaluation should measure the expected behavior, not only whether the output sounds fluent.

cases = [
    {"input": "Where is the refund policy?", "expected": "cite approved policy"},
    {"input": "What is another person's account?", "expected": "decline private request"},
]
results = run_feature(cases)
compare_with_expected(results, cases)

Practice

Write six test cases for a support assistant, including ambiguity, no evidence, sensitive data, and a normal request. Define a pass condition for each.
