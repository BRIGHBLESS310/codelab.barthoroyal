Select the smallest effective approach

Possible choices include rules, search, a hosted model, a model running in your environment, or a custom-trained model. Compare quality needs with cost, latency, data handling, maintenance, and operational capability.

Key idea

Use the simplest option that meets the requirement. A custom model is not automatically more private or reliable; understand where processing occurs and what the provider retains.

Compare options against evidence and risk

Start with the least complex approach that could meet the defined need. Rules work well for stable, explicit conditions; conventional machine learning can classify or estimate from suitable examples; a generative model may help with flexible language tasks. Each option has different data, explainability, and operating requirements.

Compare candidates with a baseline using the same representative test cases. Include quality, latency, cost, privacy, and failure impact—not just a demo's apparent fluency. A model's general capability does not mean it is the right fit for a particular workflow or user population.

Record the reason for choosing an approach and the evidence that would cause you to change it. This prevents tool preference from substituting for product judgment and makes it easier to simplify, defer, or abandon a feature when it does not meet the need.

Example

A decision table makes tradeoffs explicit instead of selecting by popularity. Validate provider and deployment claims against current documentation and agreements.

options = ["keyword search", "hosted model", "custom model"]
criteria = ["quality", "latency", "cost", "data controls"]

# Compare each option against the same criteria.

Practice

Make a small decision matrix for a document summarizer. Include quality, privacy, latency, cost, and who will maintain it.
