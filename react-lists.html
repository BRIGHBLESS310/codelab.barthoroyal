Lists and Keys

Use map to turn data into elements. Give each sibling a stable key so React can match items as the list changes. Prefer data IDs to array indexes for reorderable lists.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

JavaScript's map transforms each data item into an element, keeping content in data rather than handwritten duplicate markup. Additions, filtering, and sorting can then operate on the source array.

A key gives React a stable identity for each sibling across renders. Use a unique data ID when available; array indexes can associate state or DOM with the wrong record if items are inserted, removed, or reordered.

Keys support reconciliation and are not passed to the child as an ordinary prop. If a component needs the ID for a button or lookup, pass it separately with a descriptive prop name.

The example maps topics to list items using each id as its key. Keep IDs unique within the list and provide a useful empty state when filtering or loading leaves no items.

Example

const topics = [{ id: 1, title: "Components" }, { id: 2, title: "State" }];

function TopicList() {
  return <ul>{topics.map(topic =>
    <li key={topic.id}>{topic.title}</li>
  )}</ul>;
}

Practice

Render three tasks with stable IDs. Add or reorder an item and keep its key stable.
