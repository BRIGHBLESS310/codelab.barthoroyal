Semantic Page Layout

Explore semantic page layout through a practical example and a focused exercise.

How it works

Semantic elements describe page regions and help people navigate. Use each element according to its meaning, not its default appearance.

Build the mental model

Elements such as header, nav, main, article, section, and footer describe page regions. They give a document a useful structure that browsers, assistive technologies, and other developers can understand.

How to apply it

Choose a landmark because of the content's role, not the shape you want it to have. A page typically has one primary main; use article for independently meaningful content and a section for a named thematic group.

Common pitfalls

Semantic elements do not automatically provide visual layout or make every grouping accessible. Add headings that identify sections, reserve generic div elements for groups without a more specific meaning, and avoid using landmarks as styling hooks alone.

<header><h1>City Garden</h1></header>
<nav aria-label="Main">...</nav>
<main><article><h2>Planting guide</h2><p>...</p></article></main>
<footer>Updated May 2026</footer>

Ignore the CSS and read the example as a page outline; confirm that each landmark describes its contents and that the main content is easy to locate.

Practice

Restructure a page made of divs into meaningful regions. Include main and logical headings.
