Document Structure

Explore document structure through a practical example and a focused exercise.

How it works

Every page starts with a doctype and a root html element. The head stores document information; the body contains visible content.

Build the mental model

The doctype tells the browser to use modern, standards-based HTML parsing; it is a declaration, not an element. The root html element contains the entire document, and its lang value helps assistive technology and language-aware tools pronounce and process text.

How to apply it

The head contains metadata and resource references rather than the page's ordinary visible content. Character encoding should be declared early, the viewport setting allows a sensible mobile layout, and the title names the page in browser tabs, bookmarks, and search results.

Common pitfalls

The body holds the document content users interact with. Keep one coherent document tree, nest elements according to their parent-child relationships, and do not omit the doctype: quirks mode can make browser layout behave differently.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My Page</title>
</head>
<body><h1>Welcome</h1></body>
</html>

Trace the document from the doctype to the closing root tag; then move the heading into the head and notice why metadata and visible page content belong in different places.

Practice

Create a complete page for a hobby with a meaningful title, language, and main heading.
