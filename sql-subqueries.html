Subqueries and CTEs

A subquery nests a query inside another. A common table expression (CTE), introduced by WITH, names an intermediate result and can make multi-step queries easier to follow. EXISTS is useful when checking whether a match exists.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

A subquery is a query inside another query, such as a filter, source, or selected expression. EXISTS is useful when asking whether a related row exists, without multiplying outer rows as a join can.

A common table expression (CTE), introduced by WITH, names an intermediate result. It can make a multi-step query easier to read by separating calculation from later filtering; a CTE is not necessarily stored or cached.

A correlated subquery refers to a value from the outer query and may be evaluated for many outer rows, though optimizers can transform it. Check the query plan for expensive workloads rather than guessing performance from syntax.

The example computes each customer's total in a CTE and filters totals above 100. Choose inclusive or exclusive thresholds deliberately, and account for NULL values in the source amount.

Example

WITH order_totals AS (
  SELECT customer_id, SUM(amount) AS total
  FROM orders
  GROUP BY customer_id
)
SELECT customer_id, total
FROM order_totals
WHERE total > 100;
