Java Tutorial

Welcome to the CodeLab Java course. Java is a statically typed, object-oriented language used for server software, Android applications, desktop tools, and large business systems. Java source code is compiled to bytecode that runs on a Java Virtual Machine (JVM).

How to use this course: Follow the Java lessons in the sidebar. Each chapter explains a concept, shows code, and gives you a small exercise to try on your computer.

Java is statically typed: the compiler checks the kinds of values your code uses before the program runs. This catches many mistakes early and makes the structure of larger programs easier to reason about.

The JVM (Java Virtual Machine) runs compiled Java bytecode. Because bytecode runs on JVM implementations for different operating systems, a program can often move between platforms without changing its source code, provided the required Java version and libraries are available.

What you will learn

  • Getting started: Install a JDK, compile a Java file, and run your first program.
  • Language fundamentals: Understand statements, variables, types, operators, and control flow.
  • Reusable code: Write methods and organize data using classes and objects.
  • Practice: Compile each example and change it to test your understanding.

Your first Java program

A Java application starts running from its main method. The public class name must match the source filename.

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, CodeLab!");
    }
}

Save the code as Main.java. The Get Started lesson explains how to compile and run it.

The filename and public class name match because Java uses the public class as the named type defined by this source file. The main method has a particular signature that the Java launcher recognizes; it is the starting point, not a special kind of class.

When you compile, javac checks the source and produces bytecode, usually in Main.class. Running java Main asks the JVM to load that class and invoke its entry point. This separation helps distinguish compile-time errors from problems that only appear while the program runs.

A good way to learn

  1. Read one topic and type the example yourself instead of only copying it.
  2. Compile and run the code, then change a value or add a new case.
  3. When an error appears, read its message and check the line it points to.
  4. Build a small program that combines the concepts from several chapters.

Start with Java Get Started, then work through the sidebar chapters.

The lessons build on one another: variables hold the data that operators calculate, conditions choose a path, and loops repeat work. Methods package related steps, while classes combine data and behavior into reusable types.

When a new idea feels abstract, make the smallest program that demonstrates it, then vary one input at a time. This makes cause and effect visible and helps you connect compiler messages, program state, and output.
