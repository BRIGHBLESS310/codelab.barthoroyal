More Java Topics

Continue the Java course with methods, object-oriented programming, collections, error handling, and other commonly used features. Choose a topic from this page's sidebar.

These topics build on the fundamentals: methods help divide a problem into steps, classes model related data and behavior, and collections let programs work with groups of values. Error handling, file APIs, and debugging help make those programs dependable outside a small example.

For each topic, focus first on the problem the feature solves and the guarantees it provides. Then run a short example, change its inputs, and observe how the behavior changes before combining it with other features.

Java User Input

The Scanner class reads input from a source such as the keyboard. Create one scanner for standard input, then choose a method that matches the kind of value you expect.

import java.util.Scanner;

Scanner scanner = new Scanner(System.in);
System.out.print("What is your name? ");
String name = scanner.nextLine();
System.out.println("Hello, " + name + "!");
scanner.close();

Validate input before using it. For example, check hasNextInt() before reading a number so unexpected text can be handled clearly.

nextLine() reads the entire line, including spaces, while methods such as nextInt() read a token. Mixing token reads and line reads can make the next line appear empty because the line break after the token is still waiting in the input stream.

For a longer-running program, keep the scanner open while it is needed and close it when input is finished. Closing a scanner around System.in also closes standard input, so do not close it early if another part of the program must keep reading.

String Methods

The String class provides methods for inspecting and creating text. Strings are immutable, so methods return results rather than changing the original string.

String text = "  Learn Java  ";
System.out.println(text.trim());
System.out.println(text.toUpperCase());
System.out.println(text.contains("Java"));
System.out.println(text.replace("Java", "Code"));

Use equals() for case-sensitive value comparison and equalsIgnoreCase() when case should not matter. Avoid == for comparing string contents.

trim() removes leading and trailing whitespace, contains() checks for a substring, and replace() creates a new string with matching text changed. Since strings are immutable, the original text remains unchanged unless you assign the returned value to a variable.

String indexes count UTF-16 code units, not necessarily user-perceived characters, so indexing is not always a safe way to split arbitrary international text. For ordinary comparison and formatting, prefer the built-in string methods and be explicit about whether case and surrounding whitespace matter.

Java Scope

Scope determines where a variable can be accessed. A local variable belongs to the method or block where it is declared; a field belongs to an object or class.

class Example {
    private int field = 1;

    void show() {
        int local = 2;
        if (local > 0) {
            int blockValue = 3;
            System.out.println(field + local + blockValue);
        }
    }
}

Keep variables in the smallest scope that makes sense. This reduces accidental changes and makes code easier to understand.

A variable declared inside a block such as an if or loop cannot be used after that block ends. A local variable is created when execution enters its scope, and it must be assigned before use; unlike fields, locals do not receive default values.

Fields are associated with an object (or with a class when declared static) and remain available to that object's methods. Avoid introducing a field when a value is needed only during one method call, since wider scope makes hidden dependencies and accidental state changes more likely.

Method Parameters

Parameters name the inputs a method expects. Java passes argument values to parameters; for object references, the reference value is copied, so a method can change the object's contents but cannot replace the caller's reference variable.

static double addTax(double price, double rate) {
    return price + price * rate;
}

double total = addTax(20.0, 0.075);

Use parameter types that describe the required data and return a result when the caller needs to use it.

Java passes every argument by value. For primitive arguments the method receives a copy of the primitive value; for objects it receives a copy of the reference. The method can mutate the referenced object, but assigning a different object to its parameter does not replace the caller's reference.

Parameters form part of a method's contract. Validate values when invalid input would make the result misleading or unsafe, and use a descriptive parameter name to communicate units and meaning, such as rate rather than a generic x.

Method Overloading

Overloaded methods share a name but have different parameter lists. Java chooses a matching overload based on the number, types, and order of arguments.

static int max(int left, int right) {
    return left > right ? left : right;
}

static double max(double left, double right) {
    return left > right ? left : right;
}

A different return type alone does not create a valid overload.

Overloading is resolved at compile time from the declared argument types, number, and order. The compiler may widen a value to match a parameter, but it does not wait until runtime to choose an overload from the object's actual subtype.

Keep overloads consistent in purpose and avoid signatures that make calls ambiguous, especially when both boxed and primitive forms are present. Distinct names are often clearer when the methods do substantially different work.

Java Recursion

Recursion occurs when a method calls itself. A recursive method needs a base case that stops the calls, and a recursive step that moves toward that case.

static int factorial(int number) {
    if (number <= 1) {
        return 1;
    }
    return number * factorial(number - 1);
}

For large inputs, a loop may use less call-stack space. Check that inputs are valid and that recursion always reaches its base case.

The base case answers the smallest version of the problem directly; the recursive case reduces the input and combines its answer with the smaller result. For factorial, each call works on one smaller positive integer until it reaches the base value.

Each recursive call uses stack space, so deep recursion can cause a StackOverflowError. Also consider the valid input domain: the sample treats every value at or below one as one, which is appropriate only if negative inputs are either excluded or intentionally handled that way.

Java Constructors

A constructor initializes a new object. Its name matches the class name, and it has no return type. Define constructors to ensure objects begin in a valid state.

class Book {
    private final String title;

    Book(String title) {
        this.title = title;
    }
}

If you do not declare a constructor, Java provides a default no-argument constructor. Declaring another constructor means you need to add a no-argument version yourself if you still need one.

Constructors establish an object's initial invariants. A constructor can validate its arguments and reject impossible state instead of allowing an invalid object to be created and corrected later.

A constructor has no return type, not even void; writing a return type would declare a method instead. Constructors can be overloaded to support different valid initialization choices, and one constructor may delegate to another to avoid repeating setup.

The this Keyword

this refers to the current object. It is often used to distinguish a field from a constructor or method parameter with the same name.

class User {
    private final String name;

    User(String name) {
        this.name = name;
    }
}

In a constructor, this(...) can also call another constructor in the same class and must be its first statement.

Use this.field whenever it makes object state explicit, even if a parameter has a different name. The keyword is also useful when passing the current object to another method, though doing so during construction should be done carefully before initialization is complete.

Constructor delegation with this(...) centralizes initialization, but it must be the first statement because Java needs to choose the constructor chain before running the rest of the body. A constructor cannot use this(...) and super(...) together as separate first calls.

Java Access Modifiers

Access modifiers control where classes and members can be used. private limits access to the declaring class; public makes a member accessible wherever its containing type is accessible.

public class Account {
    private double balance;

    public double getBalance() {
        return balance;
    }
}

Java also has package-private access (no modifier) and protected. Choose the narrowest access that supports the intended design.

Package-private members are visible to classes in the same package; protected additionally supports subclass access under Java's access rules. These levels let a package cooperate internally without making every implementation detail part of a public API.

Restricting visibility reduces the number of places that can depend on a member. Start fields as private, then expose focused methods where callers need a capability; changing a public member later can break unrelated code.

Java Encapsulation

Encapsulation protects an object's state and exposes operations that preserve its rules. Private fields prevent unrelated code from assigning arbitrary values.

class Counter {
    private int value;

    void increment() {
        value++;
    }

    int getValue() {
        return value;
    }
}

Prefer meaningful operations over automatically creating a setter for every field. This lets the class maintain valid state.

Encapsulation is more than hiding fields: it means the class controls how its state changes. A deposit operation can check that an amount is positive before updating a balance, keeping the rule next to the data it protects.

For immutable data, initialize fields in a constructor and do not provide mutation methods. Immutable objects are easier to share because their state cannot unexpectedly change after construction.

Java Packages

Packages group related classes and help prevent naming conflicts. A package declaration appears at the start of a source file, before imports and the class declaration.

package com.example.school;

import java.util.ArrayList;

public class Classroom {
    private final ArrayList<String> students = new ArrayList<>();
}

Package names are commonly lowercase. The folder structure in a Java project should match the package name.

The package declaration establishes a class's fully qualified name, such as com.example.school.Classroom. Imports let source code use a type's short name, but they do not move classes or automatically include every class in another package.

Packages also organize access and project structure. In a conventional source tree, com.example.school maps to nested folders under the source root; build tools and the compiler use that relationship to find and compile types correctly.

Java Inheritance

A class can extend another class to specialize behavior. The subclass inherits accessible members and can override methods.

class Animal {
    void speak() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    @Override
    void speak() {
        System.out.println("Woof");
    }
}

Use inheritance for a genuine subtype relationship. Prefer composition when a class only needs to use another object's services.

extends declares that a subclass is also a kind of its superclass. The inherited method can be specialized with an override, while code typed to the superclass can continue to use the common behavior.

Java does not allow a class to extend multiple classes, and a superclass's private members are not directly accessible to subclasses. Keep the parent type focused on shared guarantees; use composition or interfaces when several independent capabilities are needed.

Java Polymorphism

Polymorphism lets code work with a parent type while calling behavior provided by the actual object. An overridden instance method is selected at runtime.

Animal pet = new Dog();
pet.speak(); // Woof

Program to useful abstractions so new implementations can be introduced without rewriting every caller.

The variable's declared type determines which methods are available at compile time, but an overridden instance method is selected from the actual object's class at runtime. In the example, the variable is typed as Animal while the Dog implementation supplies the sound.

This supports substitution: a method can accept an Animal and work with different animal subclasses without a separate branch for each concrete type. Polymorphism applies to overridden instance methods, not to fields or overloaded method selection.

Abstract Classes

An abstract class cannot be instantiated directly. It can define shared state and behavior, as well as abstract methods that concrete subclasses must implement.

abstract class Shape {
    abstract double area();
}

class Square extends Shape {
    private final double side;

    Square(double side) {
        this.side = side;
    }

    @Override
    double area() {
        return side * side;
    }
}

An abstract method declares behavior that concrete subclasses must supply, while implemented methods can provide shared steps. An abstract class may also hold fields and constructors, making it useful when related types share both state and a partial implementation.

Choose an abstract class when the types form a close family and need shared implementation; choose an interface when you want to describe a capability that unrelated classes can implement. A class can extend only one class but implement multiple interfaces.

Java Interfaces

An interface describes behavior a class agrees to provide. A class can implement multiple interfaces, which is useful when unrelated types share a capability.

interface Printable {
    void print();
}

class Report implements Printable {
    @Override
    public void print() {
        System.out.println("Printing report");
    }
}

Interface methods that implement public interface methods must be declared public.

Code can accept the Printable interface instead of requiring a particular class, which separates the capability from the implementation. Any class that implements the contract can be passed in, so the caller does not need to know how printing is carried out.

Interfaces can also define constants and, in modern Java, default or static methods, but their main value is a clear behavior contract. Keep that contract small and focused so implementations have a meaningful obligation.

Java Enums

An enum defines a fixed set of named constants. Enums are safer and clearer than using unexplained numeric values or strings for a limited set of choices.

enum Level {
    BEGINNER, INTERMEDIATE, ADVANCED
}

Level currentLevel = Level.BEGINNER;

Each enum constant is an instance of the enum type, so the compiler can reject misspelled or unsupported values. Use the constants in a switch or compare them directly rather than passing around fragile text labels.

An enum can include fields, constructors, and methods when each option needs associated data or behavior. Avoid relying on an enum's ordinal number as a permanent identifier, since reordering constants changes those numeric positions.

Java ArrayList

ArrayList is a resizable list from the Java Collections Framework. Use a generic type to describe the element type.

import java.util.ArrayList;

ArrayList<String> languages = new ArrayList<>();
languages.add("Java");
languages.add("Python");
System.out.println(languages.get(0));
System.out.println(languages.size());

For code that accepts a list, prefer the List interface when practical instead of requiring a specific implementation.

Generics make the element type part of the list's compile-time contract: this list accepts strings and returns strings, avoiding manual casts. Java's generic type arguments must be reference types, so use wrappers such as Integer rather than primitive int.

Use get(index) for indexed access, add to append, and size() for the current number of elements. Removing elements while iterating by index can shift later positions; an iterator or a separate collection may be safer depending on the operation.

Java HashMap

A HashMap stores key-value pairs. Keys are unique; adding a value for an existing key replaces the earlier mapping.

import java.util.HashMap;

HashMap<String, Integer> scores = new HashMap<>();
scores.put("Ada", 95);
Integer adaScore = scores.get("Ada");

A map lookup may return null when a key is absent. Check the result or use methods such as getOrDefault() when appropriate.

A map associates each key with at most one value, making it useful for lookups such as a username-to-score table. Keys must implement consistent equals and hashCode behavior; changing a key in a way that affects those methods while it is in the map can make the entry difficult to find.

Use containsKey when you must distinguish an absent key from a key explicitly mapped to null. A HashMap does not promise a predictable iteration order, so choose an ordered map if output order is part of the requirement.

Java Exceptions

Exceptions report errors or unexpected conditions. Handle an exception when your program can recover meaningfully; otherwise, allow it to propagate with useful context.

try {
    int value = Integer.parseInt("42");
    System.out.println(value);
} catch (NumberFormatException exception) {
    System.out.println("Enter a whole number.");
}

Catch specific exception types rather than hiding unrelated failures with a broad catch.

The try block marks operations that may fail, and a matching catch handles a particular exception type. Checked exceptions must be caught or declared by the method, while unchecked exceptions often indicate invalid state or programming mistakes that should not be hidden.

Handle an error where you can take a useful next step, such as asking for corrected input or reporting that a file could not be read. Avoid empty catch blocks and broad catches that make a failed operation look successful; include useful context when rethrowing or reporting an error.

Java Files

The Path and Files APIs provide a modern way to work with files. Handle possible I/O errors and use try-with-resources when managing closeable resources.

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

Path path = Path.of("notes.txt");
try {
    Files.writeString(path, "Keep practicing Java.");
    String contents = Files.readString(path);
    System.out.println(contents);
} catch (IOException exception) {
    System.out.println("Could not read or write the file.");
}

Keep file paths and permissions in mind, and avoid overwriting important files without an explicit reason.

Path represents a filesystem location, while Files provides operations such as reading and writing. A relative path like notes.txt is resolved against the program's working directory, which may differ between an IDE and a terminal.

File operations can fail because a path does not exist, permissions are insufficient, or storage is unavailable, so their checked IOException must be handled or declared. For streams and readers, use try-with-resources so resources are closed even when an exception interrupts the work.

Java Date and Time

Use the java.time API for dates and times. Types such as LocalDate represent a calendar date without a time zone.

import java.time.LocalDate;

LocalDate today = LocalDate.now();
LocalDate nextWeek = today.plusDays(7);
System.out.println(nextWeek);

Use time-zone-aware types such as ZonedDateTime when representing a moment in a particular region.

The java.time types are immutable: operations such as plusDays return a new value, leaving today unchanged. This makes date calculations easier to reason about and avoids hidden mutation.

Use LocalDate for a birthday or due date, LocalTime for a wall-clock time, and an instant or zoned date-time for an actual moment. Time-zone rules include daylight-saving changes, so a region's zone should be used when local civil time matters.

Java Regular Expressions

Regular expressions describe text patterns. Java's String methods include matches() for checking a whole string and replaceAll() for pattern-based replacement.

String code = "A123";
boolean valid = code.matches("[A-Z][0-9]{3}");
System.out.println(valid);

For user input, regular expressions are only one part of validation. Also apply the business rules and length limits your application requires.

The pattern [A-Z] matches one uppercase ASCII letter and [0-9]{3} matches three digits; together they require the entire input to have that shape because matches() checks the whole string. A pattern search method has different semantics and can match only part of a string.

In Java source, backslashes in a regular-expression pattern must also be escaped for the string literal, so a regex token such as \\d is written with a doubled backslash. Keep patterns readable and test valid and invalid examples, since dense patterns can be hard to maintain.

Java Lambda Expressions

A lambda is a concise way to provide behavior where a functional interface is expected. Lambdas are often used with collection operations.

import java.util.List;

List<String> names = List.of("Ada", "Sam", "Lin");
names.forEach(name -> System.out.println(name));

Use a lambda when it makes the operation clear; move complicated behavior into a named method.

A functional interface has one abstract method, and the lambda supplies the implementation for that method. In name -> ..., the parameter type is inferred from the context; parentheses are optional for a single parameter and braces are used for a multi-statement body.

Lambdas connect naturally to collection operations such as filtering, sorting, and mapping. Keep side effects and nested logic limited; a named method reference or helper method can make a complicated operation easier to understand and test.

Java Threads

Threads allow tasks to run concurrently, but shared mutable data needs careful coordination. For many applications, higher-level concurrency utilities are safer than manually managing threads.

Thread worker = new Thread(() ->
    System.out.println("Task running")
);
worker.start();

Calling start() begins execution on a new thread; calling run() directly executes the method on the current thread.

Concurrent tasks can make progress during overlapping time, but their execution order is not guaranteed. If multiple threads read and write shared mutable state, coordination is needed to prevent race conditions and inconsistent results.

Creating a raw thread is useful for learning the distinction, but real programs commonly use an executor to manage task scheduling and reuse threads. Prefer immutable data or thread-safe utilities where possible, and use synchronization only with a clear plan for ownership and visibility.

Java Debugging

Debugging is the process of finding and correcting the cause of unexpected behavior. Read compiler diagnostics, inspect values, and reduce a problem to a small reproducible example.

  • Read the first useful error: Later compiler messages can be consequences of an earlier mistake.
  • Check assumptions: Print or inspect values just before the incorrect result.
  • Use a debugger: Set breakpoints and step through code to see how values change.
  • Test edge cases: Try empty input, boundary values, and unexpected data.

First describe the incorrect behavior precisely, then reproduce it with the fewest steps possible. A small reproducible case helps separate the root cause from unrelated code and makes it easier to verify the fix.

A breakpoint pauses execution so you can inspect local variables and the call stack one step at a time. After changing code, repeat the same test and add a boundary or regression test so the bug is less likely to return.

Java Exercises

Apply the course topics with small, testable programs. Start with one requirement and add features only after the simple version works.

  1. Write a temperature converter using methods and numeric types.
  2. Build a quiz score summary using an array or an ArrayList.
  3. Create a simple bank account class that validates deposits and withdrawals.
  4. Read a text file and count the number of lines, handling I/O errors.

For each exercise, write down expected input and output before coding. Test normal cases first, then empty input, boundary values, and invalid input; examples become much more useful when you can explain why each result is correct.

Build incrementally: make a small method work, call it from a simple main, then add storage or object state only when the program needs it. This combines the course concepts in a way that keeps mistakes easy to locate.
