Accessibility Essentials

Explore accessibility essentials through a practical example and a focused exercise.

How it works

Accessible HTML helps people using keyboards, screen readers, magnification, and other tools. Semantics provide much of this support.

Build the mental model

Accessible HTML makes information and controls usable through different ways of perceiving and interacting with a page. Semantic elements, descriptive labels, text alternatives, and a logical reading order provide structure before any visual styling is applied.

How to apply it

Keyboard support is essential for people who cannot use a pointer and also makes focus order and available actions easier to test. Native links, buttons, and form controls already have expected keyboard behavior; preserve a visible focus indicator rather than removing it.

Common pitfalls

Accessibility cannot be added by a single attribute or automated checker. Use meaningful language and sufficient contrast, test with keyboard and zoom, and verify that custom controls announce their purpose and state as it changes.

<main>
  <h1>Event registration</h1>
  <label for="name">Your name</label>
  <input id="name" name="name" autocomplete="name">
  <button type="submit">Register</button>
</main>

Navigate the example without a mouse and inspect its structure with a screen reader or accessibility tree; identify the semantic cue that explains each control.

Practice

Review a page with keyboard navigation. Check structure, labels, alternatives, focus, and link text.
