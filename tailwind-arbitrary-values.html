Use arbitrary values selectively

Arbitrary values express a one-off CSS value in bracket notation when a design cannot be represented by the project's scales. They are useful for unusual grid tracks or a precise value, but repeated exceptions may signal a missing design token.

Key idea

Keep class names statically detectable by the build. Dynamically concatenating fragments can prevent the scanner from seeing complete class names; map user choices to complete, known class strings instead.

Escape the scale only for a real constraint

Arbitrary-value syntax places a one-off value inside square brackets, as in w-[37rem] or grid-cols-[200px_1fr]. It is useful when a design or external constraint needs a value that the configured scale does not provide; underscores can represent spaces in many arbitrary CSS values.

Arbitrary values still pass through Tailwind's build-time candidate detection. Keep the complete class name in scanned source rather than assembling pieces dynamically, or the generator may not recognize it. If a value contains special characters, follow the version-specific escaping rules.

Frequent one-off values are a signal to revisit the design scale or theme configuration. A shared token gives repeated components a consistent meaning and is easier to adjust later. Reserve bracket values for genuine exceptions, and check the emitted CSS when a custom value fails unexpectedly.

Example

The bracketed grid template is a custom value. Use it when that layout is genuinely exceptional, and prefer standard responsive utilities where they fit.

<div class="grid grid-cols-[minmax(0,1fr)_18rem] gap-6">
  <main>Flexible content</main>
  <aside>Fixed-width companion panel</aside>
</div>

Practice

Use one arbitrary value for an unusual layout, then ask whether it appears elsewhere. If it repeats, propose a shared token or component instead.
