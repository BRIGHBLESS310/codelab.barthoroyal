Plan a bounded AI prototype

A useful prototype tests one hypothesis with minimal data and a narrow feature. The prototype should have a baseline, a representative evaluation set, and explicit limits on what it may do.

Key idea

Do not expose a prototype to real sensitive data or consequential decisions without appropriate review. Label generated output as a suggestion and keep a person in control of important actions.

Turn the plan into a learning experiment

A bounded prototype should answer a specific question: can a defined AI approach improve a task for a particular user under known constraints? State the hypothesis, baseline, success measure, and stop conditions before building. This prevents an attractive demo from substituting for evidence.

Build only the path needed to test that hypothesis, but include safe data handling, representative test cases, and a fallback. Record model and prompt versions, evaluation results, latency, and cost so another person can understand what was tested and reproduce the comparison.

After the experiment, decide whether evidence supports iteration, a controlled pilot, or stopping. Note failure modes and who would bear their cost. A useful prototype creates knowledge and a responsible next decision, even when the result is that AI is not the right solution.

Example

The plan limits sources and makes a familiar search fallback available. A quality measure checks evidence rather than fluency alone.

prototype = {
    "user_need": "find an answer in public course notes",
    "sources": ["approved lesson pages"],
    "fallback": "show search results",
    "measure": "answer supported by a cited page",
}

Practice

Draft a prototype brief with user need, data boundary, architecture, success tests, risk controls, fallback, and a decision to continue or stop.

Try the example, change one detail, and explain how the result changes.
