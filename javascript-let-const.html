JavaScript let and const

let and const are block-scoped: they are available only within the block where they are declared. A const declaration must be initialized and cannot be reassigned.

Understand the topic

Block-scoped bindings

let and const are scoped to the nearest enclosing block. let permits reassignment; const requires an initial value and prevents reassignment. They avoid many confusing behaviors associated with function-scoped var.

Choose based on whether a binding changes

Prefer const when a variable continues to refer to the same value, and use let when it must be updated, such as a counter. A const object can still have changed properties: the binding is fixed, not necessarily its contents.

Scope prevents accidental collisions

A block-scoped name is unavailable before initialization and cannot be redeclared in the same scope. Do not confuse a constant binding with an immutable value. Clear names and limited scope make control flow easier to follow.

Bindings and values

The array binding stays the same even though its contents change. Prefer const unless reassignment is needed, and keep variables in the smallest useful scope.

const names = ["Ada"];
names.push("Lin");

let score = 0;
score += 10;

Practice

Try reassigning names and then adding an item to it. Observe which operation is allowed.
