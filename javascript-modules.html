JavaScript Modules

Modules split code into files and explicitly share values with export and import. In a browser, load an entry file with type=module.

Understand the topic

Split a program into reusable files

ES modules explicitly export values from one file and import them in another. This makes dependencies visible and encourages each module to have a focused responsibility. Named exports can expose several values; a default export is the module?s primary value.

Imports and exports follow rules

An imported binding is read-only in the importing module, and paths must resolve to the intended file. Browsers load entry files with <script type="module">; modules are deferred by default and use strict mode. Excessive re-export layers can obscure dependencies.

Modules differ from classic scripts

Modules have their own scope rather than placing top-level declarations on the global object. Circular imports can expose values before initialization, so avoid unnecessary cycles. Modules organize functions and objects into maintainable code.

Export and import

Modules help separate responsibilities and avoid relying on a large set of global variables.

// math.js
export function add(a, b) {
    return a + b;
}

// app.js
import { add } from "./math.js";

Practice

Move a helper function to a separate file, export it, and import it into your main script.
