Forms and Controlled Inputs

A controlled input gets its displayed value from React state and reports edits through onChange. This keeps form behavior explicit. Associate each input with a label and present validation errors in text.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

A controlled input gets its displayed value from React state and reports edits through onChange. State becomes the source of truth, so the input remains synchronized with what the component will validate or submit.

Connect each field to a label and keep its value type consistent: a text input should start with an empty string, not switch between undefined and a string. Handle submission explicitly when the app owns the flow.

Client-side checks give immediate feedback but are not a security boundary. A server must validate again because a browser can be bypassed. For larger forms, track field errors and submission status so users know what needs attention.

The example updates name from the input's change event. Extend it with a submit handler that trims and checks the value, shows an accessible error, and preserves entered text when validation fails.

Example

import { useState } from "react";

function NameForm() {
  const [name, setName] = useState("");
  return <label>Name
    <input value={name} onChange={event => setName(event.target.value)} />
  </label>;
}

Practice

Build a labeled form with a submit handler and a visible message when the field is empty.
