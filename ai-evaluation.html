Measure what matters

Evaluation compares system outputs with an appropriate reference or user outcome. Accuracy can be useful, but precision, recall, error costs, latency, and human ratings may matter more for a particular task.

Key idea

Choose measures based on consequences. A high overall score can hide poor performance for a smaller group or a critical edge case; inspect slices and representative failures.

Match the metric to the decision

Evaluation compares model outputs with a reference outcome on examples that were not used to fit the model. Accuracy is easy to understand, but it can hide poor performance on rare classes. Precision describes how often positive predictions are correct; recall describes how many actual positives were found.

There is usually a trade-off: changing the decision threshold can catch more positives while also creating more false alarms. Choose metrics and thresholds by considering the real cost of each error, not by maximizing a score in isolation. Inspect performance for relevant subgroups as well as overall averages.

Keep test examples representative of the intended use and separate them from prompt tuning or repeated model selection. For generative outputs, use a mix of criteria such as factual support, task completion, consistency, and human review. Document limitations so a score is interpreted within its scope.

Example

The tiny calculation gives two correct predictions out of three. It is not enough on its own: a larger, representative set and task-appropriate metrics are needed.

predicted = ["billing", "account", "billing"]
expected = ["billing", "billing", "billing"]

correct = sum(p == y for p, y in zip(predicted, expected))
accuracy = correct / len(expected)
