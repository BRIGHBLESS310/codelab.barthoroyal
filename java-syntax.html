Java Syntax and Output

Java uses classes, methods, braces, and semicolons to organize a program. Consistent formatting makes its structure easier to read.

Understand the program structure

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
  • Class: Main names a class, the basic building block for Java code.
  • Method: main is the entry point used to start this application.
  • Braces: { } mark the beginning and end of class and method bodies.
  • Statement: The instruction ends with a semicolon.

Read the sample from the outside inward: the class contains the main method, and that method contains the print statement. Each pair of braces must match; indentation does not change Java's meaning, but it reveals which statements belong to which block.

The words in the method signature also have specific roles: public makes it accessible to the launcher, static lets it run without first creating a Main object, and void means it returns no value. String[] args receives optional command-line arguments.

Print output

System.out.println() prints a value and starts a new line. System.out.print() prints without adding a line break.

System.out.print("Hello ");
System.out.println("there!");
System.out.println(3 + 4);

Output:

Hello there!
7

println adds a line separator after the value, while print leaves the cursor on the same line. Java evaluates the expression passed to the method first, so 3 + 4 becomes 7 before it is displayed.

Text in double quotes is a string literal, while the numbers in the example are numeric values. When you combine text and a number with +, Java converts the other value to text and concatenates it; use parentheses when arithmetic should happen before that concatenation.

Comments and readable code

Comments document intent for people reading your program. The compiler ignores comments.

// A short, single-line comment
int score = 10;

/* A comment can continue
   over several lines. */

Prefer clear names and simple formatting. A comment should explain why a decision was made rather than repeat what an obvious line already says.

A single-line comment begins with // and ends at the line break. A block comment starts with /* and ends with */; unlike documentation comments, these ordinary comments are not included in generated API documentation.

Comments do not repair code or affect execution. If a comment and the code disagree, readers must guess which is correct, so update or remove comments whenever the implementation changes. Use comments for context that cannot be expressed clearly by names and structure.

Practice

Write a program that prints your name and a number on separate lines. Add a comment that explains what the program does, then compile and run it.
