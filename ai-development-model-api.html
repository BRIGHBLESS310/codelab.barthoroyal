Integrate a model service safely

A model API usually accepts a request and returns a response over a network. Integration needs authentication, request limits, timeouts, error handling, version awareness, and a way to control cost.

Key idea

Keep provider credentials on a trusted server, never in browser code or a public repository. Send only necessary data and follow the provider's current retention and usage terms.

Treat the model provider as a dependency

A model API lets an application send an input and receive a model response over a network. The request contract may include a model identifier, instructions, messages, generation settings, and output limits; the response may contain text, usage metadata, or a structured error.

Keep credentials on a trusted server, never in browser code or a repository. Send only the data the task requires, set timeouts, handle rate limits and provider failures, and avoid logging sensitive request content by default. These are application responsibilities even when a provider manages the model infrastructure.

Provider models and APIs can change, so isolate integration details behind a service boundary. Pin or explicitly select model versions where possible and test behavior when changing them. Evaluate the complete feature, including latency and cost, rather than assuming an API response is ready to show a user.

Example

The client applies an input bound and timeout, then validates the returned value. Production code also needs authentication, rate limiting, logging controls, and provider-specific error handling.

async def summarize(text):
    response = await model_client.generate(
        input=limit_length(text),
        timeout_seconds=20,
    )
    return validate_response(response)
