Sessions and State

HTTP requests are independent. Sessions associate data with a visitor across requests, commonly for sign-in state or a temporary workflow. Start sessions before output and configure cookies securely in deployed applications.

In this lesson: Read the explanation, follow the example, and try the practice prompt before continuing.

Explanation

HTTP requests are independent. Sessions associate data with a visitor across requests, commonly for sign-in state or a temporary workflow. Start sessions before output and configure cookies securely in deployed applications.

HTTP is stateless: each request is independent. A session lets a server associate data with a visitor across requests, commonly using a session identifier stored in a cookie. Start the session before sending response output, then store only the state needed by the workflow.

Session identifiers and cookies are security-sensitive. In deployed applications, use HTTPS and appropriate cookie flags, regenerate the identifier after authentication, and avoid storing unnecessary personal data. A session is not a replacement for authorization checks on each protected action.

Example

<?php
session_start();
$_SESSION["visits"] = ($_SESSION["visits"] ?? 0) + 1;
echo "Visit " . (int) $_SESSION["visits"];
